# 배터리 추적성 설계 — 연속 공정과 이산 공정의 연결

## 왜 반도체 모델이 그대로 안 맞는가

이 리포지토리는 반도체 전제로 출발했다. 반도체는 전 공정이 이산 단위(Lot/Wafer)라
`track_in ~ track_out` 시간구간 조인만으로 계보가 성립한다.

**배터리는 다르다. 공정 전반부가 연속이다.**

| | 반도체 | 배터리 |
|---|---|---|
| 추적 단위 | Lot / Wafer (전 공정 이산) | 전극은 **연속**, 조립 이후 이산 |
| 1차 좌표 | 시간 | **위치(m)** → 시간 |
| 계보 형태 | Lot ⊃ Wafer (단순 포함) | **분기 후 수렴** |
| 공정 시간 | 시간 단위 | 화성·에이징은 **수일** |

## 좌표계 두 개와 전환점

```
[연속 좌표계]              전환점              [이산 좌표계]
(roll_id, position_m)  ──  ElectrodeLot  ──  cell_id → module_id → pack_id

  믹싱 → 코팅 → 건조 → 캘린더링 │ 슬리팅 → 노칭 │ 스태킹 → 화성 → 에이징 → 모듈 → 팩
  ←─────── 위치로만 지칭 ──────→│              │←──────── ID 로 추적 ────────→
                                 ↑
                          여기서 ID 부여
```

**`ElectrodeLot` 이 이 온톨로지의 중심축이다.** 연속 좌표계와 이산 좌표계를 잇는
유일한 고리이기 때문이다. 이 연결이 끊기면 세 가지가 동시에 불가능해진다.

- 불량 셀에서 코팅 조건으로 역추적 (근본원인 분석)
- 이상 구간이 들어간 셀 찾기 (격리·리콜 범위 산정)
- 셀 단위 재료·이력 증명 (배터리 여권)

그래서 `electrode_lot.yaml` 의 `position_start_m` / `position_end_m` 이
스키마 전체에서 가장 중요한 두 개 필드다.

## 계보 체인

```
Roll ──HAS_SEGMENT──────> WebSegment
  │                           │
  │  PRODUCES_LOT             │ SUPPLIES_LOT
  │  (position 구간 보존)      ▼
  └──────────────────────> ElectrodeLot ──SUPPLIES_CELL──> Cell
                            (CATHODE)      (N:1 수렴)        │
                            (ANODE)  ──────────┘             │ ASSEMBLED_INTO
                                                             ▼
                                                          Module ──> Pack
```

### 수렴이 반도체와의 핵심 차이

셀 하나에는 **양극 Lot 과 음극 Lot 이 각각** 들어간다. 즉 `Cell` 의 계보를 거슬러
올라가면 **서로 다른 롤의 서로 다른 구간이 복수로** 나온다.

반도체의 `Wafer BELONGS_TO Lot` 은 단순 포함이라 원천이 하나지만, 여기는 아니다.
이 사실을 모델이 표현하지 못하면 근본원인 분석이 한쪽 전극만 보게 된다.

> **수정 이력**: 기존 `cell.yaml` 에 `source_roll_id` 단일 필드가 있었다.
> "원본 롤 1개" 가정은 틀렸으므로 제거하고, 계보를 관계로 표현하도록 바꿨다.
> `cathode_lot_id` / `anode_lot_id` 는 질의 편의용 캐시일 뿐 진실의 출처가 아니다.
> 기존 `PRODUCES_CELL`(Roll→Cell 직결) 관계는 전극 Lot 단계를 건너뛰므로 deprecated.

## 추적 신뢰도를 반드시 명시한다

현실에서 셀↔롤위치 연결은 완벽히 기록되지 않는 경우가 많다.
레벨을 표시하지 않고 섞으면 분석이 조용히 오염된다.

| `traceability_level` | 의미 | 근본원인 분석에서 |
|---|---|---|
| `MEASURED` | 마킹·지문·설비 위치 출력으로 실측 | 신뢰 가능 |
| `INFERRED` | 투입 순서 + 시트 길이 + 카운트로 추정 | **참고만. 단정 금지** |
| `ROLL_ONLY` | 어느 롤인지만 알고 구간은 불명 | 구간 분석 제외 |
| `UNKNOWN` | 연결 없음 | 제외 |

**전체 계보의 신뢰도는 `Roll→Lot` 과 `Lot→Cell` 중 낮은 쪽을 따른다.**

`INFERRED` 계보로 "이 구간이 원인이다"라고 단정하면 현장에서 신뢰를 잃는다.
리포트에는 항상 레벨을 함께 표시한다.

### 해상도의 한계를 명시한다

`ElectrodeLot.position_span_m`(파생 속성)이 분석 해상도의 상한이다.
이 값이 50m 라면 롤 내 50m 안에서 일어난 편차는 Lot 단위로 구분할 수 없다.

이 숫자 자체가 사내 설득 자료가 된다 — "현재 해상도는 50m이고, 이걸 5m로
낮추면 어떤 분석이 가능해지는가"를 데이터로 보여줄 수 있다.

## 위치 좌표는 어떻게 얻는가

설비는 **시간축**으로 데이터를 내보내지만 의미는 **위치**다.

```
position_m = ∫ line_speed(t) dt
```

그리고 이 변환은 다음 구간에서 깨진다:

| 구간 | 문제 |
|---|---|
| 라인 정지 | 시간은 흐르는데 위치는 안 움직임 |
| 가감속 | 평균 속도로 적분하면 오차 누적 |
| 스플라이싱(롤 이음) | 위치 원점이 바뀜 |
| 속도 변경 | 레시피 전환 시 |

그래서 `roll_position_map` 테이블에 구간별 변환 근거를 남기고,
측정값마다 `position_confidence`(HIGH/MEDIUM/LOW)를 표시한다.
`LOW` 구간을 그대로 근본원인 분석에 쓰면 엉뚱한 구간을 지목하게 된다.

**원본 `timestamp` 는 절대 버리지 않는다.** 변환이 잘못된 것으로 밝혀지면
거기서 재계산해야 한다.

## 레인(lane)을 구분하지 않으면 신호가 사라진다

코터와 슬리터는 한 웹을 폭 방향 여러 레인으로 나눈다.
**같은 위치라도 레인별 두께가 다르다.**

레인을 구분하지 않고 평균으로 집계하면 레인 편차가 평균에 묻혀 사라진다.
그래서 `WebSegment`, `WebMeasurement`, `ElectrodeLot`, `PRODUCES_LOT` 에
모두 `lane_no` 를 둔다.

## 이 구조가 열어주는 질의 두 개

### ① 역추적 — 근본원인

> "이 불량 셀의 양극이 나온 롤 구간의 코팅 두께 거동은?"

```
Cell
 → SUPPLIES_CELL(역방향, electrode_role=CATHODE) → ElectrodeLot
 → PRODUCES_LOT(역방향) → Roll + [position_start_m, position_end_m)
 → web_measurements 범위 질의
```

결과는 **항상 복수의 롤 구간**이다 (양극·음극 각각). 하나로 뭉뚱그리면 안 된다.

### ② 순추적 — 영향 범위 ★

> "코팅 두께가 이상했던 롤 120~135m 구간이 들어간 셀을 전부 찾아라"

```
Roll + [120, 135)
 → PRODUCES_LOT (구간 겹침) → ElectrodeLot
 → SUPPLIES_CELL → Cell → ASSEMBLED_INTO → Module → Pack
```

구간 겹침 조건:
```sql
rel.position_start_m < :query_end AND rel.position_end_m > :query_start
```

②가 사업적으로 더 중요할 수 있다. **격리·리콜 범위 산정**이고,
배터리 여권의 추적성 요구와도 직결된다.

## 규제 연계 — 같은 계보가 두 가지를 동시에 만족한다

**EU 배터리 규정 2023/1542**: 2027년 2월 18일부터 EV·LMT·2kWh 초과 산업용
배터리에 디지털 배터리 여권이 의무화된다 (EU 중앙 등록소는 2026년 7월 출범).

여권은 셀 단위의 재료 구성, 탄소발자국, 재생원료 비율 증명을 요구한다.
**그러려면 계보가 끊기지 않아야 한다.**

```
이상감지 온톨로지 (내부 가치)  ─┐
                              ├─ 같은 계보 데이터
배터리 여권 대응 (규제 강제)   ─┘
```

이상감지는 "있으면 좋은 것"이지만 여권은 "못 하면 EU에 못 파는 것"이다.
**같은 데이터 기반이므로 하나를 만들면 둘 다 얻는다.** 사내 예산 근거로도 강하다.

구현 표준은 **Catena-X AAS + SAMM Aspect Model** 로 정해져 있으므로,
`ElectrodeLot.material_lot` 등을 여기에 정렬해 두면 나중에 연동이 쉬워진다.
