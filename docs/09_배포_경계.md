# 반출 경계 — 무엇이 코어이고 무엇이 사내 전용인가

## 왜 이 문서가 있는가

이 리포지토리는 두 가지를 동시에 담는다.

- **코어** — 표준 기반 범용 프레임워크. 도메인 방법론. 다음 현장에서도 그대로 쓴다.
- **사이트** — 사내 실제 테이블·컬럼명, 채워진 전문가 지식, 접속 정보, 실데이터.

둘을 섞으면 나중에 분리할 수 없다. 커밋 이력이 남기 때문이다.
그래서 **사내 실데이터가 이 리포지토리에 닿기 전에** 경계를 물리적으로 그어 둔다.

## 원칙 — 익명화가 아니라 분리

익명화는 커밋할 때마다 "이건 지워도 되나"를 판단해야 한다.
수백 번 판단하면 몇 번은 반드시 틀린다.

**분리는 한 번만 판단하면 된다.** 코어에 사내 값이 애초에 존재하지 않으면
실수할 여지가 없다.

```
┌─ 코어 (추적됨) ─────────────────────────────────┐
│  common/            프레임워크, Action 계층      │
│  api/ analytics/    범용 로직                    │
│  ontology/schemas/  표준 기반 스키마              │
│    └ sourceMapping: 예시만 (<컬럼명> 형태)        │
│  scripts/           범용 도구                     │
│  docs/              방법론                        │
└──────────────────────────────────────────────┘
                   ↑ 런타임에 주입
┌─ 사이트 (.gitignore) ───────────────────────────┐
│  config/site/mappings/   실제 테이블·컬럼명       │
│  config/site/knowledge/  채워진 전문가 지식        │
│  config/site/secrets/    접속 정보                │
│  landing/                실데이터                  │
│  profiles_out/           프로파일 산출물           │
└──────────────────────────────────────────────┘
```

## 전문가 지식 — 양식과 내용을 가른다

가장 민감한 항목이라 별도로 정한다.

`analytics/templates/expert_knowledge_template.xlsx`는 **양식**이므로 코어에 둔다.
채워진 파일은 `config/site/knowledge/`로 간다.

그리고 내용 안에서도 한 번 더 갈린다.

| | 성격 | 예 |
|---|---|---|
| **정성 인과** (반출 가능) | 업계 공통, 논문·교과서 수준 | "코팅 두께 변동은 셀 용량 편차로 이어진다" |
| **정량 조건** (반출 불가) | 그 회사의 실측·조건·임계값 | "두께 편차 ±1.2µm 초과 시 용량 3% 감소" |

정성적 인과 방향은 대체로 업계 공통이고, **정량적 조건·수치·임계값이 회사 고유**다.
양식의 열 자체를 이 기준으로 나누면 판단이 쉬워진다.

> 익명화로는 이 항목을 해결할 수 없다. 파라미터 코드를 바꿔도 내용이 남으면
> 노하우를 그대로 옮긴 것이고, 내용을 지우면 가치가 0이 된다.
> 그래서 **양식만 가져가고 내용은 현장마다 새로 채운다.**

## 기계적 방어

판단을 사람에게만 맡기지 않는다.

### 1. `.gitignore`

`config/site/**`가 통째로 제외되며 `README.md`와 `*.example.yaml`만 추적된다.
`landing/`, `profiles_out/`, `*.parquet`도 제외 대상이다.

### 2. pre-commit 훅

```bash
git config core.hooksPath .githooks     # 한 번만 실행
```

커밋 직전에 `scripts/check_leaks.py --staged`가 돌아 아래를 막는다.

- `config/site/`의 실제 파일이 스테이징된 경우
- 사이트 고유 패턴이 코어 파일에 들어간 경우
- 자격증명·접속 문자열로 보이는 값
- 데이터 파일(`.parquet` / `.csv` / `.xlsx`) — 단, `templates/`는 제외

사이트 고유 패턴 목록은 `config/site/leak_patterns.txt`에 둔다.
그 목록 자체가 사내 정보(설비 ID 접두어, 테이블명 체계)이므로 추적에서 제외된다.
`leak_patterns.example.txt`를 복사해 채운다.

### 3. 감사

```bash
python scripts/check_leaks.py --all     # 추적 중인 전체 파일 점검 (보고만)
```

### 4. 비식별 프로파일러

실데이터를 밖으로 내보내지 않고 구조만 파악한다.

```bash
python scripts/profile_site_data.py --landing /path/to/landing
```

기본 설정에서 산출물에 들어가는 것은 컬럼명·타입·널 비율·고유값 개수·
시각 범위·수치 요약통계뿐이다. 실제 값은 포함되지 않는다.
산출 폴더 `profiles_out/`도 `.gitignore` 대상이며, **공유 전에 내용을 직접 확인한다.**

## 시작 절차

```bash
# 1. 훅 설치
git config core.hooksPath .githooks

# 2. 사이트 오버레이 준비
cp config/site/mappings/battery.example.yaml config/site/mappings/battery.yaml
cp config/site/leak_patterns.example.txt config/site/leak_patterns.txt
#    -> 사내 실제 값으로 채운다 (둘 다 커밋되지 않는다)

# 3. 실데이터 구조 파악
python scripts/profile_site_data.py --landing /path/to/landing \
    --mapping config/site/mappings/battery.yaml

# 4. 보고서 검토 후 매핑 완성
#    profiles_out/site_profile.md
```

## 남은 항목

- [ ] 이미 추적 중인 대용량 CSV 분리
      (`analytics/results/*.csv`, `analytics/sample_data/*.csv` — 약 11MB)
      `.gitignore`에 규칙은 넣었으나 기존 추적 파일에는 적용되지 않는다.
      제거하면 다른 사용자의 체크아웃에서도 사라지므로 판단이 필요하다.
- [ ] 사내 프로젝트가 공식 과제인지 개인 시범인지에 따른 권리 관계 정리
      (고용계약의 직무발명·겸업 조항 확인, 가능하면 착수 전 서면 합의)
